# 📋 任务拆解与工程规划指南 (Plan & Execution Pipeline)

本技能提供宏观任务拆解、工单拓扑调度与状态机流转的标准工程方法论。通过结构化的依赖分析与前沿推进，杜绝“盲目盲读”、“串行游荡”与“局部防御性修补”。

---

## 1. 任务拆解核心范式：工单图谱与就绪前沿 (Ticket Graph & Frontier)

凡涉及多步骤（>2 步）、跨模块调研或复杂功能开发，必须通过 `todo_write` 建立并维护结构化任务清单：

1. **垂直切片 (Tracer Bullets)**：
   - 坚决避免按层切片的水平划分（如“先写完所有后端，再写所有前端”）；
   - 每个任务片应是一条窄而完整穿透各层（数据契约/后端/前端/测试）的垂直链路，单个切片自包含、可独立验证与演示。
2. **声明阻塞依赖 (Blocking Edges)**：
   - 明确标注每个任务的前置依赖，无阻塞任务构成**就绪前沿 (Frontier)**；
   - 调度策略：始终优先执行处于 Frontier 上的就绪任务。多任务互不依赖时，强制并发处理。
3. **动态流式更新 (Living Checklist)**：
   - 每完成一个前沿步骤，立即通过 `todo_write` 的 `update` 动作打勾（`completed`），并动态解锁下游阻塞任务，保持上下文绝对清晰。

## 2. 全生命周期配套技能衔接 (The Skill Ecosystem)

规划技能作为智能体开发的中枢，与生态中专业技能协同流转：

```text
[构想/质询]                     [规格/拆解]                    [实现/测试]                  [质量门禁]
grill-with-docs/domain-modeling ──> to-spec / to-tickets ──> implement / tdd (Seams) ──> code-review / check
       │                                │                              │                            │
       └─────────────────────────────> plan (todo_write 状态机维护) ───┴────────────────────────────┘
```

1. **需求质询与领域建模 (`grill-with-docs` / `domain-modeling`)**：
   - 消除模糊术语与隐藏假设，统一定义领域实体与边界，锁定架构深模块（Deep Module）。
2. **规格提炼与工单拆解 (`to-spec` / `to-tickets`)**：
   - 将业务意图整理为严谨规格书（用户故事、外部接缝 Seams、实现与测试决策、排除范围）；
   - 拆解为带 Blocking Edges 的敏捷工单，输入给 `plan`。
3. **图谱拓扑与并发分治 (`code_explore` / `task`)**：
   - 复杂未知模块优先调用 `code_explore` 检索语义图谱与读写位点；
   - 3+ 独立模块并发派发 `task` 子代理，主线程把控前沿推进与契约整合。
4. **测试驱动与接缝落地 (`implement` / `tdd`)**：
   - 仅在预先约定的公共接缝（Seams）编写测试，执行 Red → Green 垂直循环，拒绝耦合私有内部实现。
5. **双轴审查与环境进化 (`code-review` / `retro`)**：
   - Standards（代码坏味道/规范）与 Spec（需求合规/防范围蔓延）双轴审查；
   - 复盘将教训固化为自动化门禁与规则指针。

## 3. 交互级状态机流控（组件与业务下沉模型）

> 注：原“如果/判断/回退/执行/跳转”模型下沉为**具体前端组件交互与业务流控的健壮性实现规范**，不再作为宏观工程规划流水线：

- **如果 (If)**：校验触发前置条件与权限状态；
- **判断 (Check)**：轻量前置检测（格式、边界、容量）；
- **回退 (Fallback)**：异常平滑降级（如封面失效自动降级、音源超时切换备用源）；
- **执行 (Execute)**：非阻塞原子更新（行内就地响应，严禁阻断式交互）；
- **跳转 (Jump)**：无感流畅闭环（无需强制重载页面）。
